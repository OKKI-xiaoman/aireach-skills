## 0. 初始化

本技能依赖 OKKI AiReach 能力，执行前必须先确认 `aireach-cli` 可用且当前环境已授权。若缺少 `aireach-cli`，请先通过 npm 安装：`npm install -g @okki-aireach/aireach-cli`（或由宿主按插件约定注入），不要尝试绕过 CLI 直接调用内部接口。

执行前运行 `aireach-cli auth status` 检查登录状态，确认本地凭证与目标 gateway 环境匹配。若未登录或凭证失效，先按 `okki-aireach-auth-init` 的流程引导用户完成授权（授权 URL 需包含 `client_id=accio-work`），授权成功后再继续本技能任务。

不要要求用户粘贴或展示 PAT/token，也不要把授权登录路径、内部地址写进回复；认证是否可用以目标 gateway 的真实请求验证结果为准，而不是只看本地是否有 token。
## Email Trust Verifier (邮箱可信度核验器)
### 核心任务
当用户对某个联系方式（邮箱）产生质疑，或要求验证邮箱有效性时，通过外部联网搜索、第三方权威接口、内部触达记录三个维度进行交叉比对，输出置信度报告。

### 触发条件
用户显式要求： "验证这个邮箱"、"这个联系方式准吗"、"核验邮箱有效性"。
意图识别： 用户表达对联系方式的质疑，如 "客户一直不回，邮箱是不是挂了？"、"确认下这个人的联系方式"。

### 执行逻辑 (三步核验法)
**第一步：外部数字足迹检索 (Web Footprint)**
- 目标： 确认邮箱活跃度，并通过公司与人员背景进行逻辑推断。
- 操作： 使用 web_search 进行分段检索：
    1. **完全匹配**：搜索 "example@domain.com"。
    2. **公司与人员校验**：提取前缀 (example) 与域名 (domain.com)，分别确认公司是否存在，以及是否有公司高管或员工的姓名缩写/组合符合该前缀的生成逻辑（例如 "lwoo" 匹配 "Liyuan Woo"）。
- 搜索关键词： "example@domain.com"、"domain.com" company background、"Liyuan Woo" domain.com。
- 存证要求： **必须**在报告中展示找到该邮箱或推断依据的 **页面标题** 及 **URL 证据链接**。
**第二步：权威第三方收录核验 (Official Data)**
- 目标： 确认该邮箱是否被顶级商务数据库正式收录及其新鲜度。
- 官方平台： 重点核验 Apollo 和 Snovio。
- 操作： 调用 `aireach-cli tool contact_validity_check --input '{"emails":["邮箱地址"]}'`。
- 数据点： 必须获取 **收录时间 (create_time)** 以辅助判断邮箱是否为陈旧数据。
- 判定标准： 状态为 "Verified" 且收录时间较新时置信度最高。
**第三步：内部触达记录校验 (OKK Internal Records)**
- 目标： 基于内部互动数据对邮箱进行最终定级。
- 操作： 通过 `aireach-cli` 返回的 `mail_level_name` 进行口径对齐。
- 定级口径：
    - **GOOD**：有打开、回复的互动行为，或者被多次有效触达等。
    - **GENERAL**：近期有成功发送记录。
    - **UNKNOWN**：缺少足够的发送和行为记录。
    - **RISK**：近期发送记录连续失败或发送成功率偏低。
    - **ABSENT**：联系方式不可用。

### 输出规范
核验完成后，必须按以下格式输出报告（注意使用空行确保换行生效）：

**🛡️ 邮箱置信度核验报告**

- **核验对象**：[邮箱地址]
- **综合置信度**：[极高 / 高 / 中 / 低]

**🔍 证据链核验详情：**

| 核验维度 | 状态/级别 | 详情描述与证据链接 |
| :--- | :--- | :--- |
| **外部数字足迹** | [发现足迹 / 逻辑匹配 / 未发现] | **必须详细描述**推理逻辑或发现路径（如：高管背景、离职入职时间线、前缀命名规则匹配等）。<br>证据链接：[必须提供的 URL 地址] |
| **权威平台收录 (Apollo & Snovio)** | [已收录 / 未收录] | **必须详细描述**收录的平台、具体的收录日期、数据新鲜度以及是否为当前职务关联的数据。 |
| **OKKI 内部评级** | [GOOD / GENERAL / UNKNOWN / RISK / ABSENT] | **必须严格按口径详细描述**（例如：GOOD - 记录显示该邮箱在近期有打开、回复等深层互动行为，非单纯发送成功）。 |

💡 **最终建议**： [一句话总结建议，基于以上维度给出行动指引]

### 异常处理
无 OKK 权限： 若接口返回 401，应在报告中说明：“因未登录 OKK 账号，无法核验官方数据及内部记录，仅提供外部检索结果。”
检索无果： 若三方均为零发现，置信度标记为“低”，并提醒用户注意风险。
