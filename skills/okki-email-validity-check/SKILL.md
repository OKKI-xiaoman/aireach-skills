# Email Trust Verifier (邮箱可信度核验器)
### 核心任务
当用户对某个联系方式（邮箱）产生质疑，或要求验证邮箱有效性时，通过外部联网搜索、第三方权威接口、内部触达记录三个维度进行交叉比对，输出置信度报告。

### 触发条件
用户显式要求： "验证这个邮箱"、"这个联系方式准吗"、"核验邮箱有效性"。
意图识别： 用户表达对联系方式的质疑，如 "客户一直不回，邮箱是不是挂了？"、"确认下这个人的联系方式"。

### 执行逻辑 (三步核验法)
**第一步：外部数字足迹检索 (Web Footprint)**
- 目标： 确认该邮箱在公开互联网上的活跃度和关联性。
- 操作： 使用 web_search 工具并提取具体来源。
- 搜索关键词： "example@domain.com"、"example@domain.com" site:linkedin.com。
- 存证要求： 必须在报告中展示找到该邮箱的 页面标题及 URL 链接，作为实锤证据。
**第二步：权威第三方收录核验 (Official Data)**
- 目标： 确认该邮箱是否被顶级商务数据库正式收录。
- 官方平台： 重点核验 Apollo 和 Snovio。
- 操作： 通过 `aireach-cli` 获取这两个平台的收录状态。
- 判定标准： 记录在案且状态为 "Verified" 或 "Professional" 时增加置信度。
**第三步：内部触达记录校验 (OKK Internal Records)**
- 目标： 基于历史互动数据对邮箱进行定级。
- 操作：通过  `aireach-cli` 获取。

### 输出规范
核验完成后，必须按以下格式输出报告：

**🛡️ 邮箱置信度核验报告**
核验对象： [邮箱地址] 综合置信度： [极高 / 高 / 中 / 低]

**🔍 证据链核验详情：**
外部检索详情 (数字足迹)：
状态：[发现足迹 / 未发现]
描述：发现于 [页面标题]
证据链接：[URL 地址]
权威平台收录 (Apollo & Snovio)：
状态：[已收录 / 未收录]
描述：[例如：Apollo 已收录，Snovio 未收录]
OKK 内部通道数据：
状态标记：[优质 / 一般 / 未知 / 风险 / 不存在]
描述：[例如：近期有成功触达记录，属于活跃联系方式]
💡 最终建议： [一句话总结建议]

### 异常处理
无 OKK 权限： 若接口返回 401，应在报告中说明：“因未登录 OKK 账号，无法核验官方数据及内部记录，仅提供外部检索结果。”
检索无果： 若三方均为零发现，置信度标记为“低”，并提醒用户注意风险。
